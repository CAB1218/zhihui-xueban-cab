# 个性化学习建议模块说明（理解教学 — 个性化学习建议）

> 面向赛题「任务 3」的实现说明。只讲这一块怎么做的、为什么这么给建议、材料从哪来、结论怎么追。

## 1. 赛题要求与实现的对应关系

| 赛题原文 | 本模块的实现 |
|---|---|
| 结合学习要求 | 复用任务1 的课程大纲：每条建议绑定 `units.contents`（topic / requirement / requirement_level / cognitive_level / suggested_hours / textbook_ref） |
| 结合学情分析结果 | 复用任务2 的个体摘要：需巩固 / 基本掌握 / 证据不足 + 每条结论的证据记录 ID 与正确率 |
| 结合任务条件 | 支持「周期（3/7/14 天）」「教师指定优先补强知识点」「课程」三个条件 |
| 明确建议内容 | 每条建议给出：学习内容（3 条）+ 练习（诊断/变式/综合三段）+ 活动建议 |
| 对应材料或练习 | `materials` 分三类：教材章节（大纲出处）、资源库已上传文件（带 resource_id）、按规则登记的自建材料（写清筛选/出题规则） |
| 选择理由 | 每条 `reason` 由「学情依据 + 课程要求 + 班级共性 + 教师指定」拼成，逐项可核 |
| 必要的先后安排 | 先按大纲单元顺序排，再用大纲 `connections`（先修关系）做稳定拓扑；并按天排期（每天 ≤60 分钟） |
| 回应分析发现的问题与需求 | 需巩固项逐条对应；「基本掌握」只在没有需巩固项时补位 |
| 便于实施及教师调整 | 每条给验收标准 + 教师调整提示（题量/时间/是否改小组活动）；整体给课堂讲评建议 |
| 信息不足时可提出补充观察或练习建议 | 证据不足的知识点单独出「补充观察」：3 次诊断练习 + 明确的判定规则，不预设「没学会」；无任何记录的学生按大纲前两个单元给基线诊断 |
| 涉及资源时能对应到具体材料 | 材料清单汇总去重，标注「出处（课程大纲/资源库/按规则登记）」与「用于第几步」 |

## 2. 数据从哪来

| 输入 | 来源 | 备注 |
|---|---|---|
| 学情结论 | `learning_records`（任务2 同源，含导入数据） | 阈值与任务2 完全一致：单知识点 ≥3 次才判断、<60% 需巩固、≥80% 掌握良好 |
| 学习要求 | `curriculum_outlines.outline`（任务1 产出） | 取该课程最新一份 `status=completed` 的大纲；找不到时降级为通用层次，并在界面与报告中说明 |
| 材料 | `resources`（资源库）+ 大纲 `textbook_ref` | 按知识点在资源标题/描述/标签里做匹配，命中才列 |
| 学生信息 | `users`（可导入，见第 6 节） | 姓名用于匹配学情记录 |

## 3. 生成逻辑

### 3.1 选哪些知识点补

1. 取任务2 个体摘要的 `needs_consolidation`（需巩固），数量上限 4；
2. 不足 2 条时，从 `fair_areas` 里取正确率最低的 1 条补位；
3. 教师指定 `focus` 命中时插到第一位；
4. `insufficient_evidence` **不进入补强清单**，单独走「补充观察」。

### 3.2 怎么对到大纲

按分数取最优匹配，避免「排序」被「拓扑排序与关键路径」抢走：

| 匹配方式 | 分数 | 例子 |
|---|---|---|
| 单元名 == 知识点 | 100 | 排序 → 单元「排序」 |
| 内容标题 == 知识点 | 95 | 图的遍历 → 内容「图的遍历」 |
| 内容标题以知识点开头 | 80 | 查找 → 「查找算法…」 |
| 单元名包含知识点 | 75 | 树与二叉树 → 「树与二叉树」 |
| 内容标题包含知识点 | 65 | 哈希表 → 「散列表」（经别名） |

别名表 `TOPIC_ALIASES` 处理记录里的通俗叫法：哈希表↔散列表、串与数组↔串/数组、树与二叉树↔二叉树的遍历等。

单元级命中时取「学时最多」的 2 条内容，避免一次推整章。

### 3.3 先后安排怎么来

1. 先按单元顺序（`unit_index`）+ 内容顺序（`content_index`）稳定排序；
2. 扫大纲 `connections`：若 `from_topic` 与 `to_topic` 分别属于方案里的两条建议，则前者必须先于后者，用 Kahn 拓扑调整；
3. 每条生成 `order_reason`：
   - 前置也在本方案 → 「先学 A 再练 B：<大纲给的理由>」
   - 前置不在本方案 → 「B 需要 A 打底；若 A 也不牢，先花 20 分钟补它」
4. 按天排期：单条 25–60 分钟（按大纲学时折算），每天 ≤60 分钟；中间空档标「缓冲」，最后一天「复盘与复测」。

### 3.4 材料怎么登记

| kind | 含义 | 例子 |
|---|---|---|
| `textbook` | 教材章节，来自大纲 `textbook_ref` | 严蔚敏《数据结构（C语言版）》第 10 章 |
| `resource` | 资源库真实文件（带 `resource_id`） | 《排序算法动画讲解.mp4》 |
| `rule` | 按规则登记的自建材料，规则写清可复现 | 「排序」错题重练卷：`knowledge_point=排序 且 is_correct=false`，倒序取 10 题 |

`rule` 类材料的规则同时出现在界面与导出报告里，保证「按规则登记」可追溯，而不是凭空写一个资料名。

## 5. 接口清单

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/learning-advice/courses` | 课程下拉（不依赖 `/teachers/*`，学生也能取） |
| GET | `/api/v1/learning-advice/students` | 学生列表（含记录数、正确率、证据是否充足）；学生身份只返回自己 |
| POST | `/api/v1/learning-advice/generate` | 生成方案并落库；无记录也返回「补充观察」型方案 |

| GET | `/api/v1/learning-advice/plans/{id}/export` | 导出 Markdown |
| POST | `/api/v1/learning-advice/students/import` | 导入学生名单（csv / xlsx） |
| GET | `/api/v1/learning-advice/students/import/template` | 学生名单模板 |

## 6. 学生信息导入

页面右上角「导入」下拉两个入口：

1. **学生名单**（本模块新增）：姓名必填，邮箱选填（留空自动生成占位邮箱），可带年级/专业/学校。已有邮箱跳过，坏行不入库并返回行号与原因。默认密码 `student123`。
2. **学情记录**（复用任务2 的导入）：按「学生姓名」匹配已建号学生，导入后重新生成建议即可用上新数据。

> 为什么分成两个：建议必须基于学情，但「先有学生」是前提。没有学情也能生成——会转成补充观察型方案，正好覆盖赛题「信息不足」的情形。
