## 附录 A　系统运行与演示步骤

### A.1 环境准备

| 项目 | 要求 | 说明 |
|------|------|------|
| Docker Engine | 24.0+ | 全部服务以容器方式运行，宿主无需装 Python / Node / 数据库 |
| Docker Compose | **v2.24+** | 编排文件使用了 `env_file: path/required` 语法，低版本会解析报错 |
| 内存 | ≥ 8 GB（推荐 16 GB） | Elasticsearch 固定 512 MB 堆、Neo4j / ClickHouse 各需数百 MB |
| 磁盘 | ≥ 10 GB | 镜像约 3 GB，赛题 PDF 与数据卷约 1 GB |
| 端口 | 80 / 8000 / 5432 / 7474 / 7687 / 8123 / 9001 / 9002 / 9003 / 6379 / 9200 | 80 为唯一对外入口，其余为本机运维端口 |
| 可选（本地开发） | Node 18+、Python 3.11 | 仅在前端热更新或后端源码调试时需要 |

大模型能力需在 `backend/.env` 填入 `DEEPSEEK_API_KEY`；**未配置也能完整启动**，此时对话类功能自动降级为内置规则引擎（界面标注「离线回答 · 未调用大模型」）。

### A.2 启动服务

```bash
# 1. 获取代码
git clone https://github.com/CAB1218/zhihui-xueban-cab.git
cd zhihui-xueban-cab/deploy

# 2. 一键拉起 10 个容器（首次会构建后端镜像，约 3—5 分钟）
docker compose up -d --build

# 3. 确认 10 个容器均为 Up，有状态服务显示 healthy
docker compose ps

# 4. 执行数据库迁移（首次或代码更新后）
docker exec ai4edu-backend alembic upgrade head

# 5. 导入赛题模拟学情数据（幂等脚本，可重复执行）
docker exec ai4edu-backend python scripts/import_contest_data.py
```

启动完成后浏览器访问 <http://localhost>，默认账号 `admin@ai4edu.com` / `admin123`。
（容器内数据库、存储桶等标识统一沿用 `ai4edu`，属技术标识，与对外展示名「智慧学伴」并存，改动会导致账号与数据失效。）

### A.4 故障备用方案

| 现象 | 处置 |
|------|------|
| 页面白屏 | `Ctrl + Shift + R` 强制刷新（PWA Service Worker 缓存导致，nginx 已对 `index.html`、`/sw.js` 关缓存） |
| 接口 502 / 连不上后端 | `docker compose restart backend`；nginx 已用 `resolver 127.0.0.11` + 变量 `proxy_pass`，后端换 IP 不会持续 502 |
| 表不存在 / 字段缺失 | `docker exec ai4edu-backend alembic upgrade head` |
| 数据被改乱 | 重跑 `python scripts/import_contest_data.py`（脚本幂等，会先按 13 张表清理再导入） |
| 现场无网络 | 预构建镜像 + `docker save/load` 离线分发；演示视频与截图见 A.3 路径 |

### B.2 如何定位每一次生成结果（本项目不设 `logs/` 目录）

遵循 12-factor 原则，进程日志统一输出 **stdout**，由 Docker 接管（避免容器内写文件导致卷膨胀）。因此「某次结果是怎么生成的」按三层逐层收窄：

| 层 | 入口 | 能看到什么 |
|----|------|------------|
| ① 运行日志 | `docker compose logs --since 30m backend`；Celery 任务用 `logs celery-worker` | 请求时间、接口路径、异常栈、任务执行记录 |
| ② 业务数据表 | `docker exec ai4edu-postgres psql -U ai4edu -d ai4edu` | `curriculum_outlines`（大纲生成，含 `model_name` 与时间）、`learning_records`（每条作答及 `raw_payload` 原始字段）、`agent_sessions` / `agent_messages`（对话全量）、`resources`（文件入库记录） |
| ③ 交付清单 | `任务成果包/manifest.json` | 199 个文件的 SHA-256 与生成时间，可判断交付物是否被改动、是否同一次生成 |

示例：核对「D03 第 3 条建议的依据」→ ② 用 `evidence_record_ids` 查 `learning_records` 对应行 → 取 `raw_payload` 的材料编号与评分点得分 → 回 `contest_materials` 定位题目与切片。全程不依赖日志文件，结论可独立复核。

### B.3 Docker 配置（打开智能体时加载的编排文件）

> **说明：以下即点击打开 AI Agent 智能体（执行 `docker compose up -d`）时加载的 Docker 编排配置全文**，与仓库 `deploy/docker-compose.yml` 逐字一致，可直接用于评审对照。10 个容器由一份文件编排：前端 1 + 后端应用 3（API / worker / beat）+ 数据与中间件 6（PostgreSQL / Neo4j / ClickHouse / Redis / Elasticsearch / MinIO）。

编排要点：

| 要点 | 做法 | 原因 |
|------|------|------|
| 镜像数量 | 只构建 1 个镜像（backend），worker / beat 复用同一镜像仅改 `command` | 省构建时间与磁盘 |
| 前端 | 不自建镜像，用 `nginx:1.25-alpine` 只读挂载 `frontend/dist` | 改前端只需 `vite build`，无需重建容器 |
| 服务发现 | 单一自定义 bridge 网络 `ai4edu-network`，容器间用**服务名**互访 | 容器重建换 IP 不受影响 |
| 启动顺序 | 6 个有状态服务配置 `healthcheck`，backend 用 `condition: service_healthy` 等待 | 避免连不上数据库导致崩溃重启 |
| 配置注入 | `app/config.py` 默认值 → `env_file: ../backend/.env`（`required: false`）→ `environment` 强制覆盖 host | 没有 `.env` 也能「克隆即跑」，容器内一律走服务名 |
| 持久化 | 7 个 named volume | 删容器不丢数据；`down -v` 才会清空 |
| MinIO | 用 `bitnamilegacy/minio`（官方镜像 2025 年已从 Docker Hub 下架） | 端口与 API 与官方一致，仅数据目录需 root 初始化 |

```yaml
services:
  # ============ 前端 ============
  frontend:
    image: nginx:1.25-alpine
    container_name: ai4edu-frontend
    ports:
      - "80:80"
    volumes:
      - ../frontend/dist:/usr/share/nginx/html:ro
      - ./nginx/conf.d/default.http.conf:/etc/nginx/conf.d/default.conf:ro
    depends_on:
      - backend
    restart: unless-stopped
    networks:
      - ai4edu-network

  # ============ 后端 ============
  backend:
    build:
      context: ../backend
      dockerfile: Dockerfile
    container_name: ai4edu-backend
    ports:
      - "8000:8000"
    env_file:
      # backend/.env 不入库（含 API Key）。缺失时回退到 app/config.py 默认值，
      # 容器内的 host 相关配置由下方 environment 覆盖，因此没有 .env 也能启动。
      - path: ../backend/.env
        required: false
    environment:
      - POSTGRES_HOST=postgres
      - NEO4J_URI=bolt://neo4j:7687
      - CLICKHOUSE_HOST=clickhouse
      - REDIS_HOST=redis
      - MINIO_ENDPOINT=minio:9000
      - MINIO_PUBLIC_ENDPOINT=121.43.129.181
      - ELASTICSEARCH_HOST=http://elasticsearch:9200
      - CELERY_BROKER_URL=redis://redis:6379/1
      - CELERY_RESULT_BACKEND=redis://redis:6379/2
    depends_on:
      postgres:
        condition: service_healthy
      redis:
        condition: service_healthy
      neo4j:
        condition: service_healthy
    restart: unless-stopped
    networks:
      - ai4edu-network

  # ============ Celery Worker ============
  celery-worker:
    build:
      context: ../backend
      dockerfile: Dockerfile
    container_name: ai4edu-celery-worker
    command: celery -A app.core.celery_app worker --loglevel=info --concurrency=4
    env_file:
      # backend/.env 不入库（含 API Key）。缺失时回退到 app/config.py 默认值，
      # 容器内的 host 相关配置由下方 environment 覆盖，因此没有 .env 也能启动。
      - path: ../backend/.env
        required: false
    environment:
      - POSTGRES_HOST=postgres
      - NEO4J_URI=bolt://neo4j:7687
      - REDIS_HOST=redis
      - MINIO_ENDPOINT=minio:9000
      - MINIO_PUBLIC_ENDPOINT=121.43.129.181
      - ELASTICSEARCH_HOST=http://elasticsearch:9200
      - CLICKHOUSE_HOST=clickhouse
      - CELERY_BROKER_URL=redis://redis:6379/1
      - CELERY_RESULT_BACKEND=redis://redis:6379/2
    depends_on:
      redis:
        condition: service_healthy
      postgres:
        condition: service_healthy
    restart: unless-stopped
    networks:
      - ai4edu-network

  # ============ Celery Beat ============
  celery-beat:
    build:
      context: ../backend
      dockerfile: Dockerfile
    container_name: ai4edu-celery-beat
    command: celery -A app.core.celery_app beat --loglevel=info
    env_file:
      # backend/.env 不入库（含 API Key）。缺失时回退到 app/config.py 默认值，
      # 容器内的 host 相关配置由下方 environment 覆盖，因此没有 .env 也能启动。
      - path: ../backend/.env
        required: false
    environment:
      - POSTGRES_HOST=postgres
      - NEO4J_URI=bolt://neo4j:7687
      - REDIS_HOST=redis
      - MINIO_ENDPOINT=minio:9000
      - MINIO_PUBLIC_ENDPOINT=121.43.129.181
      - ELASTICSEARCH_HOST=http://elasticsearch:9200
      - CLICKHOUSE_HOST=clickhouse
      - CELERY_BROKER_URL=redis://redis:6379/1
      - CELERY_RESULT_BACKEND=redis://redis:6379/2
    depends_on:
      redis:
        condition: service_healthy
    restart: unless-stopped
    networks:
      - ai4edu-network

  # ============ PostgreSQL ============
  postgres:
    image: postgres:16-alpine
    container_name: ai4edu-postgres
    ports:
      - "5432:5432"
    environment:
      POSTGRES_DB: ai4edu
      POSTGRES_USER: ai4edu
      POSTGRES_PASSWORD: ai4edu_password
    volumes:
      - postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U ai4edu"]
      interval: 10s
      timeout: 5s
      retries: 5
    restart: unless-stopped
    networks:
      - ai4edu-network

  # ============ Neo4j ============
  neo4j:
    image: neo4j:5.20
    container_name: ai4edu-neo4j
    ports:
      - "7474:7474"
      - "7687:7687"
    environment:
      NEO4J_AUTH: neo4j/neo4j_password
      NEO4J_PLUGINS: '["apoc"]'
    volumes:
      - neo4j_data:/data
      - neo4j_logs:/logs
    healthcheck:
      test: ["CMD-SHELL", "wget -q --spider http://localhost:7474 || exit 1"]
      interval: 15s
      timeout: 10s
      retries: 5
    restart: unless-stopped
    networks:
      - ai4edu-network

  # ============ ClickHouse ============
  clickhouse:
    image: clickhouse/clickhouse-server:24.1
    container_name: ai4edu-clickhouse
    ports:
      - "8123:8123"
      - "9001:9000"
    environment:
      CLICKHOUSE_USER: default
      CLICKHOUSE_PASSWORD: clickhouse_password
    volumes:
      - clickhouse_data:/var/lib/clickhouse
    healthcheck:
      test: ["CMD-SHELL", "clickhouse-client --password clickhouse_password --query 'SELECT 1'"]
      interval: 15s
      timeout: 10s
      retries: 5
    restart: unless-stopped
    networks:
      - ai4edu-network

  # ============ Redis ============
  redis:
    image: redis:7-alpine
    container_name: ai4edu-redis
    ports:
      - "6379:6379"
    volumes:
      - redis_data:/data
    healthcheck:
      test: ["CMD", "redis-cli", "ping"]
      interval: 10s
      timeout: 5s
      retries: 5
    restart: unless-stopped
    networks:
      - ai4edu-network

  # ============ Elasticsearch ============
  elasticsearch:
    image: elasticsearch:8.13.0
    container_name: ai4edu-elasticsearch
    ports:
      - "9200:9200"
    environment:
      - discovery.type=single-node
      - xpack.security.enabled=false
      - "ES_JAVA_OPTS=-Xms512m -Xmx512m"
    volumes:
      - es_data:/usr/share/elasticsearch/data
    healthcheck:
      test: ["CMD-SHELL", "curl -f http://localhost:9200/_cluster/health || exit 1"]
      interval: 15s
      timeout: 10s
      retries: 5
    restart: unless-stopped
    networks:
      - ai4edu-network

  # ============ MinIO ============
  minio:
    # 注意：官方 minio/minio 镜像已于 2025 年从 Docker Hub 下架（pull 会 403），
    # 改用 Bitnami 打包的同版本 minio 服务端（API、控制台端口与用法完全一致）
    image: bitnamilegacy/minio:latest
    container_name: ai4edu-minio
    user: "0:0"   # 数据卷由 root 创建，需以 root 运行才能初始化
    ports:
      - "9002:9000"
      - "9003:9001"
    environment:
      MINIO_ROOT_USER: minioadmin
      MINIO_ROOT_PASSWORD: minioadmin
      MINIO_DATA_DIR: /data
      MINIO_API_PORT_NUMBER: "9000"
      MINIO_CONSOLE_PORT_NUMBER: "9001"
    volumes:
      - minio_data:/data
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:9000/minio/health/live"]
      interval: 10s
      timeout: 5s
      retries: 5
    restart: unless-stopped
    networks:
      - ai4edu-network

# ============ 数据卷 ============
volumes:
  postgres_data:
    driver: local
  neo4j_data:
    driver: local
  neo4j_logs:
    driver: local
  clickhouse_data:
    driver: local
  redis_data:
    driver: local
  es_data:
    driver: local
  minio_data:
    driver: local

# ============ 网络 ============
networks:
  ai4edu-network:
    driver: bridge
```
